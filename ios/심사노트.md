## 1. App Review Information → Notes 에 붙여 넣을 영문 (오늘선생)

```
ABOUT THIS APP
"오늘선생" (Today Teacher) is a private tool for a one-on-one after-school
math tutor to manage a single student's lessons: recording what was covered,
assigning worksheets, reviewing the student's handwritten solutions, and
drafting a progress message for the parent.

It is the teacher-side companion to "오늘학생" (Today Student), which the
student uses on an iPad. The two apps exchange worksheets and submissions.

NO ACCOUNT IS REQUIRED
The app opens directly in DEMO MODE with no sign-in. Every screen and feature
is reachable without any credentials. Cloud sync and AI question generation
are optional and only activate if the user enters their own Supabase project
URL / API key under the "설정" (Settings) tab — we do not ship any keys.

HOW TO REVIEW
1. Launch the app. It opens on the "오늘" (Today) tab in demo mode.
2. Tap "오늘 수업 종료" (End today's lesson) to see the core flow:
   progress → homework → one comment → an auto-composed parent message.
3. "수업 기록" shows saved lessons and messages.
4. "문제지·자료" is where a worksheet is created and sent to the student app,
   and where submitted answers and photos of handwritten work are reviewed.
5. "학생" holds the student profile, scores and weak-point notes.

CAMERA USAGE
The camera is used only to photograph paper worksheets and handwritten
solutions so they can be attached to a lesson record. Nothing is uploaded
unless the user has configured their own cloud project.

WORKS OFFLINE
All assets are bundled locally; the app runs without a network connection.

The interface is Korean, as the app is for Korean tutoring.
```

### 겪은 함정 (다음 앱에서 반복하지 말 것)

1. **아이콘 알파 채널** — 512×512 + 투명도였다. App Store는 1024×1024·알파 없음만 받는다. 업로드 단계에서야 걸리므로 미리 확인할 것.
2. **CSS 특이성** — 세이프에어리어 규칙을 `.t-hd`로 넣었는데 원본이 `#tutor-overlay header.t-hd`(1,1,1)라 무시됐다. 시뮬레이터로 눈으로 보기 전까지는 "적용된 줄" 알았다.
3. **`</body>`가 두 개** — JS 문자열 안에도 `</body>`가 있어서, 앞에서부터 치환하면 스크립트가 문자열 속에 박힌다. 반드시 `rpartition`으로 마지막 것을 잡을 것.
4. **무한 리로드** — 시드 스크립트의 early-return을 없애면서 `location.reload()`가 매 로드마다 실행돼 화면이 백지가 됐다. 백지 화면을 보면 먼저 리로드 루프를 의심할 것.
5. **www에 임시 파일이 남음** — `sync-web.sh`가 vendor만 지우고 www는 유지해서 시드 파일이 잔존했다. **www를 통째로 재생성**하도록 고쳤다.

### 서명·업로드에서 겪은 함정 (2026-08-18)

6. **개인(Individual) 계정은 팀원이 인증서를 못 만든다** — App Store Connect에는 관리자로 들어가도
   developer.apple.com에는 `Certificates, Identifiers & Profiles` 메뉴 자체가 없다.
   해결: 계정을 공유하지 않고, 내 맥에서 CSR을 만들어 계정 소유자에게 보내 인증서·프로파일만 받았다.
   소유자는 브라우저에서 10분 작업, Xcode 설치도 불필요. → `ios/signing/창욱이형에게_부탁.md`
7. **OpenSSL 3.x가 만든 .p12를 macOS가 못 읽는다** — `MAC verification failed (wrong password?)`.
   원인은 암호가 아니라 최신 암호화 알고리즘. `-legacy` 플래그로 다시 묶어야 한다.
8. **WWDR 중간 인증서가 없으면 인증서가 "유효하지 않음"** — import는 성공했다는데
   `find-identity`가 0개를 반환한다. `AppleWWDRCAG3.cer`를 같이 설치해야 체인이 완성된다.
9. **`errSecInternalComponent`** — codesign이 키체인의 개인키를 못 꺼내 쓰는 상태.
   `security set-key-partition-list`는 로그인 키체인 암호를 요구해 자동화가 막힌다.
   해결: **빌드 전용 키체인을 새로 만들어** 거기에 인증서를 넣으면 암호를 내가 정하므로 권한 부여가 된다.
   (CI 표준 방식) → `parohans-build.keychain-db`
10. **스크린샷 규격 착오** — 6.9"(1320×2868)를 찍었는데 App Store Connect가 요구한 건
    6.5"(1284×2778)와 13" iPad(2064×2752)였다. 6.9→6.5는 비율차 0.4%라 리사이즈로 해결되지만,
    iPhone→iPad는 비율이 달라 반드시 해당 시뮬레이터에서 다시 찍어야 한다.
11. **URL 필드가 한글 경로를 거부** — `docs/설명서.html`을 넣으면 저장 버튼이 오류를 낸다.
    퍼센트 인코딩하거나 영문 파일명 사본(`guide.html`)을 만들어야 한다.
12. **"사용권 계약"은 판매 지역이 아니다** — EULA 설정 화면에서 두 번째 옵션을 고르면
    약관 전문을 직접 써야 한다. Apple 표준 EULA(첫 번째)를 고르면 끝.
    판매 국가 제한은 `가격 및 사용 가능 여부`에서 따로 한다.
13. **연령 등급의 UGC·메시지 판단** — 형식만 보면 "예"지만, 애플이 잡으려는 건 *공개 배포*와
    *낯선 사람 연결*이다. 1:1 페어링 구조라 "아니요"로 답하고, 그 근거를 심사 메모에 명시했다.
    "예"로 답하면 Guideline 1.2가 걸려 신고·차단 기능을 요구받는다.

### 스크린샷 만드는 법 (재현 절차)

시뮬레이터 조작 권한 없이 찍기 위해, 데모 시드를 임시로 주입하고 탭을 자동 순회시켰다.

```bash
# 1) 시드 주입 (반드시 마지막 </body> 앞)
cp seed-demo.js ios/teacher/www/ && python3 -c "
import pathlib; p=pathlib.Path('ios/teacher/www/index.html'); t=p.read_text()
h,s,tl=t.rpartition('</body>'); p.write_text(h+'<script src=\"seed-demo.js\"></script>\n</body>'+tl)"
# 2) 빌드·설치·실행 후 6초 간격으로 캡처
# 3) 끝나면 반드시: ./ios/sync-web.sh  (www를 재생성해 시드를 지운다)
```

시드 데이터는 **전부 가명(홍길동·한빛고)**을 쓴다. 실제 학생 정보를 스토어 스크린샷에 노출하지 않기 위함이다.
설정 탭은 실제 페어링 코드가 보이므로 스토어 스크린샷에서 제외했다.

## 7. 제품 방향 결정 (2026-08-18)

**이 앱은 개인 도구로 유지한다.** App Store 등록은 배포 전 과정을 익히는 학습이 목적이었고,
그 목적은 달성했다. 일반 사용자를 받는 서비스로 전환하지 않는다.

**왜 지금 구조로는 공개 배포가 불가능한가** (전환을 재검토할 때 이 조건들을 먼저 해결해야 한다):

- `supabase-setup.sql`의 RLS 정책이 `using(true)` — anon 키를 가진 누구나 모든 행을 읽고 지울 수 있다.
  사용자 격리는 `pair_code` 문자열 하나뿐이다.
- 손풀이 사진 버킷이 public 읽기 — URL을 알면 누구나 열람 가능. **미성년자 사진이라 특히 위험**.
- 로그인 개념이 없다. 공개하려면 Auth 도입 + RLS를 `auth.uid()` 기준으로 전면 재작성해야 하고,
  App Store 규정상 소셜 로그인을 쓰면 Sign in with Apple도 필수다.
- Gemini 키가 클라이언트 입력식이라, 우리가 부담하려면 Edge Function 프록시와 사용량 제한이 필요하다.
- 비용: Supabase 무료 티어는 스토리지 1GB. 손풀이 사진이 주 소비원이라 선생님 수십 명이면 Pro($25/월)로 넘어간다.

**현재 상태의 의미**: 심사에는 문제가 없다(심사원은 데모 모드로 전 기능 확인 가능).
공개되더라도 일반 사용자는 데모 화면까지만 보게 되며, 실사용은 자신의 Supabase를 연결한 사람만 가능하다.
